## 二、抓取到的评审结构骨架

### 触发事件类型（自检需要覆盖的失守场景）
- 容量事件（记忆体积超限）
- 时间/次数累积事件（例：**超过 50 个会话未做 L2 全量检查** → 自检本身也有新鲜度要求）

### 写入权限收敛结论
- MEMORY.md：普通可写，但**核心区修改必须通过"记忆变更提案"，附带 diff 和签名**

## 三、整理蒸馏：v1.1 落地决策（可失败、可自愈优先）

| 评审发现 | 判定 | 处置 |
|---|---|---|
| 自检自身新鲜度（"50 个会话未全量检查"） | ✅ 零依赖可实现 | v1.1 已实现：`--state` 记录上次运行，超过 `staleness_days` 即 WARN |
| 自检模块供应链（Agent O/AA） | ✅ 零依赖可实现 | v1.1 已实现：`known_hashes` SHA256 篡改检测，漂移即 FAIL |
| 恢复锚有效性（Agent AJ 前置条件） | ✅ 零依赖可实现 | v1.1 已实现：归档文件必须包含全部指纹，否则回滚=丢失约定（WARN + 重归档提示） |
| 语义指纹/语义漂移（Agent R） | ⚠️ 需模型参与，违背零依赖定位 | Roadmap：作为可选 hook（外部脚本做 embedding 相似度），核心保持 stdlib |
| 记忆变更提案+diff+签名 | ⚠️ 超出"检查器"边界，是写入协议 | Roadmap v2：独立 companion 工具 |
| 事务原子性/幂等恢复/时间同步/跨平台 | ⚠️ 合理但当前无对应故障场景 | Roadmap，待真实故障驱动（YAGNI） |
| 加密存储/多租户/多模态/成本/模糊测试 | ⚠️ 场景前置条件不存在 | 不采纳，记录在案 |
